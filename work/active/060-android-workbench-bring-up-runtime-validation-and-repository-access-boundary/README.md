# 060 — Android Workbench Bring-Up, Runtime Validation, and Repository-Access Boundary

**Status:** Active

**Owner:** tooling-owner

**Affected scopes:** tooling, work, docs, evidence

**Depends on:** WI058, WI059

## Intent

Turn the existing Tauri Workbench (WI055, extended by WI057/WI058) into a
real Android-runnable application on this Precision's actual Android SDK/
emulator environment, exercise the compact/mobile IA WI058 designed (whose
Android runtime evidence was explicitly left unexecuted), and classify the
production Android repository-access boundary honestly.

**In scope:** the mobile-capable Cargo/Tauri crate shape, Android project
initialization, a debug-only app-private validation repository, on-device
runtime/UI/Back/orientation/safe-area validation, and an explicit decision
about the production repository-acquisition boundary (with a follow-up work
item if that boundary remains unresolved).

**Out of scope:** iOS/macOS bring-up; choosing or implementing a production
mobile repository-acquisition architecture (that is follow-up work, not
WI060); reopening WI058 or WI059; any change to WI050 admission/guard
authority.

## Decisions

See `architecture-review.md` for the baseline facts this item is built on,
and the final report/evidence for what was actually decided about the
production repository-access boundary.

evidence. WI060 closes only when Android runtime evidence is durable (not
merely a successful Gradle/cargo build) and the Windows regression baseline
remains green. See `work-item.json` for exact criteria.
